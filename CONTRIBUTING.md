# Contributing to the Vibe Coding Guide

Want to add your own vibe-coded projects or improve the guide? Hell yeah! 🌊

## How to Contribute

### Adding Your Project

1. **Vibe code something cool**
2. **Add it to `/examples`**
3. **Include comments explaining your vibe coding process**
4. **Submit a PR**

### What Makes a Good Example?

- **Shows the process** - Comments explaining how you built it
- **Actually works** - Can be messy, but should run
- **Has "next vibes"** - List what you'd add if you kept going
- **Demonstrates a principle** - Start simple, ship fast, iterate later, etc.

### Guidelines (Loose, Because Vibes)

✅ **Do:**
- Share projects at any stage (working prototype = perfect)
- Include time estimates (helps others see what's possible)
- Be honest about shortcuts taken
- Show the messy version (it's instructional!)
- Have fun with comments and docs

❌ **Don't:**
- Submit "perfect" polished code (that's not vibe coding!)
- Remove comments that show your thought process
- Over-engineer examples to look impressive
- Gatekeep - all skill levels welcome

## Improving the Guide

Found a typo? Have a better explanation? Want to add a section?

1. **Make the change**
2. **Submit a PR**
3. **That's it**

No need to open an issue first. Just vibe code the improvement.

## Project Ideas We'd Love to See

- Mobile apps (React Native, Flutter)
- Game dev examples (Unity, Godot)
- Hardware/IoT projects (Arduino, Raspberry Pi)
- Creative coding (P5.js, Processing)
- CLI tools in different languages
- Web scraping projects
- Data viz projects
- Whatever weird thing you built at 2am

## The Vibe Code of Conduct

1. **Be kind** - We're all learning
2. **Be helpful** - Share what worked for you
3. **Be real** - Show the messy parts too
4. **Have fun** - That's the whole point

## Questions?

Open an issue or just submit your PR. We'll figure it out together. That's vibe coding. 🌊
